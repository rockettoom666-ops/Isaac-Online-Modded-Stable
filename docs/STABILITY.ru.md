# Экспериментальный форк: совместимость кооператива

Статус: **предварительная версия, сетевой тест на двух компьютерах не проведён**.
Это форк патчера xADDBx, а не новый сетевой движок. Включение модов не делает
произвольный Lua-код синхронным. Вылет после удержания R остаётся отдельным,
не подтверждённым как исправленный сценарием.

## Версия 1.4.1-preview.4

Новый присланный лог J460 фиксирует desync на кадре 121: отличается
`PostVelocity` одного игрока при одинаковых контрольных суммах общего RNG и
сохранения. В этом запуске не зарегистрировано прежней Lua-ошибки CuerLib.
Это не доказывает установку патча и не указывает на конкретный мод.
Отбрасывание дублирующего пакета ввода само по себе не доказывает неисправность сети.

В этой версии сбрасываются история ввода и таймер определения локального игрока
CuerLib при старте забега, включая удержание R. Иначе первые кадры нового забега
могли использовать нажатия из предыдущего. Защита EID дополнена окном рецептов
Bag of Crafting: оно больше не меняет `ControlsCooldown` при нескольких игроках.
Описания и просмотр рецептов сохраняются. Эти дефекты воспроизведены отдельно
на Lua с имитацией API; их связь именно с desync на кадре 121 не установлена.

Также исправлена версия XML Coming Down; это устраняет известное несоответствие
формата, а не является доказанным исправлением рассинхронизации движения.
Формат `version="5"` приведён в [примере entities2.xml](https://isaacblueprints.com/tutorials/crash_course/entity_basics/).

В заголовке окна отображается версия патчера. Пустая/неверная папка теперь
вызывает отдельную ошибку. **Export mod report...** сохраняет статусы правил,
пути и SHA256 Lua/XML установленного набора без изменения модов.
`applied` — правило установлено, `pending` — нужно применить, `unsupported` —
код отличается, `MISSING` — отсутствует файл. Сравните отчёты обоих игроков;
настройки модов в сохранениях этот отчёт не проверяет.

Обновление с preview.3: распакуйте новый архив в отдельную папку, закройте игру,
на обоих компьютерах нажмите **Apply mod safety workarounds...** и укажите
`C:\Program Files (x86)\Steam\steamapps\common\The Binding of Isaac Rebirth\mods`.
Восстанавливать EXE, моды или сейвы перед обновлением не нужно.
**EID Patched: Yes** относится к старому отдельному патчу EID и не подтверждает
установку всех защит ввода. После установки перезапустите игру.

## Что изменено

- **Coming Down! [Rework] (2878352867):** исправлен подтверждённый в логе
  Lua-краш `ZoneLink` при очистке опасности. Удаление теперь выполняется
  только если ссылка существует. Для Repentance+ также исправляется версия
  схемы `content/entities2.xml` с `1` на `5`; J460 сообщал `Invalid version 1`.
  Ошибка в `PostUpdate` могла оставить клиентов с разным состоянием и закончиться
  киком одного игрока.
- **emote-binds (3034946842):** очередь отложенных действий очищается при
  `MC_POST_GAME_STARTED`. Действия с захваченными ссылками на персонажа из
  предыдущего забега больше не должны запускаться после быстрого рестарта.
- **The Specialist for Good Items (2575911103):** обход игроков исправлен
  с `1..N` на `0..N-1`, чтобы не пропускать первого игрока и не запрашивать
  игрока за концом списка. Это не подтверждение полной совместимости мода.
- **CuerLib (2900345009):** исправлена подтверждённая ошибка в
  `cuerlib/class/netcoop.lua:279`. `GetPlayerIndex` возвращает индекс с нуля,
  а `table.remove` и `table.insert` требуют индексы Lua с единицы. Из-за этого
  возникало `bad argument #1 to 'remove' (position out of bounds)`, после чего
  игра фиксировала desync и удаляла второго игрока.
- **EID (836319872):** в режиме совместимости отключены ввод текста поиска
  рецептов и блокировка управления через Item Reminder при числе сущностей
  игроков больше одной. Описания и просмотр рецептов остаются доступны.
- **Mod Config Menu — Impure (3701683951):** в этом режиме меню нельзя открыть,
  а его обработчики не подменяют ввод в игре с несколькими сущностями игроков.
- **emote-binds:** в этом режиме локальные клавиши эмоций не обрабатываются
  при числе сущностей игроков больше одной. Эмоции могут менять анимацию,
  размер, RNG и даже убивать персонажа, поэтому это ограничение функции,
  а не реализация сетевой синхронизации эмоций.
- **Antibirth Music+++ из исходного репозитория:** удалён неиспользуемый
  `Random()` при смене комнат; исправлена граница обхода игроков.
- **Patch Game:** co-op и analytics проверяются в памяти перед единственной
  записью EXE. Ошибка второй сигнатуры больше не оставляет применённой только
  первую часть операции. Новые сигнатуры игры не добавлены.

Детектор ограничений использует `Game():GetNumPlayers() > 1`, а не
`EID.isMultiplayer`: последний зависит от настроек описаний. Ограничения
затрагивают также локальный кооператив и одиночных персонажей с дополнительными
сущностями (например, Jacob & Esau). Это намеренный компромисс до проверки
надёжного определения онлайн-сессии для конкретной версии игры.

## Установка

1. Закройте игру и дождитесь завершения обновлений Steam Workshop.
2. Запустите `IsaacOnlineModded.exe` из этой предварительной сборки на Windows.
3. Выберите `isaac-ng.exe`. `Patch Game` нужен только для включения модов в
   онлайн-режиме; если сигнатуры неизвестны, патчер откажется от записи.
4. Кнопка `Patch External Item Descriptions` применяет прежнюю защиту EID
   после Beast. Это отдельный патч.
5. Нажмите **Apply mod safety workarounds...** и выберите папку **mods** игры,
   содержащую папки установленных модов. Можно также выбрать
   `steamapps/workshop/content/250900`, если это используемая игрой копия.
6. Ознакомьтесь с ограничениями и списком файлов в окне подтверждения.
   Будут обработаны только шесть указанных выше Workshop ID с распознанным
   кодом. Один неподдерживаемый файл отменяет весь план до записи.
7. Выполните те же действия у второго игрока. Полностью перезапустите игру.

Патчи Antibirth Music+++ устанавливаются отдельно по инструкции в его папке.
Музыкальный мод не присутствовал на присланных фотографиях и не объясняет
описанный пользователем вылет.

Обновление Workshop может заменить изменённые файлы. После обновлений
проверьте патчи повторно. Повторное применение к уже исправленным файлам
не меняет их и не добавляет дубликаты.

## Откат

Для каждого файла режима совместимости сохраняется оригинал:
`имя.lua.iom-<SHA256 оригинала>.bak`. Закройте игру, скопируйте нужный оригинал
поверх `имя.lua`. Копии после нескольких обновлений могут различаться:
восстанавливайте версию, соответствующую текущему моду. Можно переустановить
мод из Workshop вместо ручного отката. Эти резервные копии относятся к новой
кнопке совместимости, не к старому EXE/EID-патчеру.

Для удаления изменений EXE используйте проверку файлов игры в Steam.
Для старого отдельного патча EID — переустановку/обновление EID.

## Проверка удержания R

Записывайте версию Repentance+, одинаковые ли сборки у обоих игроков,
персонажей, хозяина лобби и точное действие перед рассинхронизацией.

1. Сначала повторите тест без модов и с оригинальным EXE.
2. Затем с патчером и одним EID, включая защиту ввода.
3. Сделайте 20 быстрых рестартов удержанием R, после каждого двигайтесь
   обоими игроками и переходите в другую комнату. Это предлагаемый тест,
   не результат выполненной здесь проверки.
4. Повторите с шестью поддержанными модами и применёнными исправлениями.
5. Если проблема исчезла, возвращайте остальные моды половинами списка.
   Сверяйте версии и настройки обоих игроков.
6. Отдельно проверьте старт с хорошим предметом, подбор предмета, эмоции,
   открытие MCM, поиск EID, Jacob & Esau и обычных персонажей.

`Reroll Until Good Item` и `Ice Bird` на присланных фото выключены: не следует
приписывать им эту ошибку. Моды синергий, TimeMachine, изменения пьедесталов и
остальные моды пока не проверены на сетевую совместимость.
Для точной диагностики нужен `desync_log.txt` и `log.txt` из неудачного запуска
**с обоих компьютеров**. Совпадающие хеши модов сами по себе не гарантируют
синхронизацию: локальный ввод и сохранённые настройки тоже могут отличаться.

## Автоматические проверки

- `dotnet run --project tests/Regression`: проверки записи, сигнатур,
  повторной установки, BOM/переводов строк и резервных копий.
- `python -m pip install lupa==2.8`
- `python tests/test_lua.py`: проверка музыкального кода на Lua 5.4 с имитацией API.
- Дополнительно скопируйте поддержанные моды в отдельную временную папку,
  примените `dotnet run --project tests/Regression -- --patch-fixture-directory <копия>`
  и выполните `python tests/test_lua.py <копия>` для проверок поведения их Lua.
  Никогда не передавайте в этот тест рабочую папку модов.

Тесты с имитацией API не воспроизводят сетевой движок Isaac. Сборка Windows
на macOS проверяет компиляцию, но не запуск окна WPF и не игру.
